# izicrm — Excel-отчёт

Отчёт за всё время по кнопке `[📊 Excel-отчёт]`. Строится автоматически из PostgreSQL.
Содержит данные **только запросившего пользователя** (FR-7.4).

Имя файла: `izicrm_<YYYY-MM-DD>_<HHmm>.xlsx`. Идентификаторы пользователей в имя не попадают.

---

## 1. Конвейер генерации

```
ReportQueryRepository (SQL: только выборка строк)
        ↓
ReportDatasetBuilder (domain: все расчёты в Decimal)
        ↓
ReportDataset  ← чистая структура данных, полностью покрыта unit-тестами
        ↓
XlsxWriter (port) → адаптер библиотеки
        ↓
Buffer → sendDocument → удаление временного файла
```

Библиотека — `@office-kit/xlsx` с нативными графиками (ADR-006, решение принято 20.08.2026).
`ReportDataset` от неё не зависит: смена адаптера не затрагивает ни бизнес-логику, ни тесты
расчётов. Ни одной формулы P&L в генераторе файла нет — он получает готовые числа. Это
исполнение NFR-8: второго источника истины не появляется.

Значения записываются как **числа с числовым форматом**, не как текст: иначе Excel не сможет
строить графики и агрегировать. Преобразование `Decimal → number` выполняется **только здесь**,
на самой границе вывода, и это единственное разрешённое в проекте место (см. `.cursor/rules/financial-math.mdc`).

## 2. Структура книги

Восемь листов. Порядок соответствует пути анализа: от итогов к деталям.

| # | Лист | Назначение |
|---|---|---|
| 1 | `Сводка` | KPI за всё время + основные графики |
| 2 | `Динамика` | Ряд по фактическим датам обновлений |
| 3 | `Месяцы` | Месячная агрегация |
| 4 | `Балансы карт` | Матрица дата × карта |
| 5 | `Карты` | Реестр карт |
| 6 | `Движения капитала` | Журнал внешних потоков |
| 7 | `Календарь` | Служебный ежедневный ряд для графиков (скрыт) |
| 8 | `Инфо` | Метаданные, определения, оговорки |

---

### Лист 1. `Сводка`

Блок KPI (метка + значение), затем графики.

| Показатель | Определение |
|---|---|
| Текущий капитал | `Cap(u, today)` |
| Внесено всего (депозиты) | `TotalDeposits` |
| Выведено всего | `TotalWithdrawals` |
| Начальный капитал | `Cap(u, первая дата активности)` |
| Прибыль за всё время | `TotalPnL` (модель §5.4) |
| Доходность за всё время | `TotalPnL / TotalDeposits` |
| Доходность (Modified Dietz) | Модель §5.5 |
| Среднегодовая доходность (CAGR) | `(1 + TotalReturn)^(365/дней) − 1`, при ≥ 90 днях наблюдения |
| Прибыль за текущий месяц | ₽ и % |
| Прибыль за последний период | ₽, %, число дней |
| Лучший день | Дата и сумма максимального `DailyPnL` |
| Худший день | Дата и сумма минимального `DailyPnL` |
| Средний дневной P&L | Среднее по фактическим наблюдениям |
| Медианный дневной P&L | Устойчив к выбросам |
| Прибыльных / убыточных / нулевых наблюдений | Счётчики |
| Доля прибыльных наблюдений | Прибыльные ÷ все наблюдения |
| Максимальная просадка ₽ и % | По ряду **накопленного P&L**, не по капиталу — см. ниже |
| Волатильность дневной доходности | σ дневных `%`, информационно |
| Дней наблюдения | `today − первая дата + 1` |
| Число обновлений | Количество фактических дат |
| Активных / архивных карт | Счётчики |
| Первое / последнее обновление | Даты |

**Просадка считается по накопленному P&L, а не по капиталу.** По капиталу вывод денег при
архивировании карты выглядел бы как просадка, хотя убытка не было. Ряд накопленного P&L очищен
от внешних потоков и поэтому отражает реальный результат.

Графики на этом листе:

| График | Тип | Данные |
|---|---|---|
| Капитал по времени | Линейный | `Календарь`: дата → капитал |
| Накопленный P&L | Линейный с заливкой | `Календарь`: дата → накопленный P&L |
| Дневной P&L | Столбчатый | `Динамика`: дата → P&L ₽ |
| Месячная прибыль и доходность | Комбинированный: столбцы ₽ + линия % на второй оси | `Месяцы` |
| Структура капитала | Кольцевой | Текущие балансы активных карт |

### Лист 2. `Динамика`

Только фактические даты обновлений — §9 требует сохранять фактические даты и не создавать
синтетических записей.

| Столбец | Формат | Примечание |
|---|---|---|
| Дата | `dd.mm.yyyy` | Фактическая дата обновления |
| Дней с предыдущего | `0` | `periodDays`; > 1 означает пропуск |
| Капитал | `# ##0.00 ₽` | `Cap(u, D)` |
| Депозиты за период | `# ##0.00 ₽` | |
| Выводы за период | `# ##0.00 ₽` | |
| P&L ₽ | `+# ##0.00 ₽;−# ##0.00 ₽` | Цветовая шкала |
| P&L % | `+0.00%;−0.00%` | Пусто, если база ≤ 0 |
| Накопленный P&L ₽ | `# ##0.00 ₽` | |
| Просадка от максимума ₽ | `# ##0.00 ₽` | |
| Обновлено карт | `0` | Сколько карт получили запись в этот день |

Первая строка ряда: `P&L` и `P&L %` пусты (нет предыдущего дня, FR-5.6). Пустая ячейка, не ноль.

### Лист 3. `Месяцы`

| Столбец | Примечание |
|---|---|
| Месяц | `ГГГГ-ММ` |
| Капитал на начало | `Cap(S − 1)` — закрытие предыдущего месяца (C-4) |
| Депозиты | За месяц |
| Выводы | За месяц |
| Капитал на конец | `Cap(E)` |
| Прибыль ₽ | Модель §5.3 |
| Доходность % (простая) | `PnL / Cap(S−1)` |
| Доходность % (Modified Dietz) | Модель §5.5 |
| Доходность % (time-weighted) | `Π(1 + rᵢ) − 1` по дневным наблюдениям |
| Обновлений в месяце | Счётчик |

Три метрики доходности рядом — не избыточность: они расходятся ровно тогда, когда в месяце
были внешние потоки, и это расхождение и есть полезная информация (C-16).
Контрольная сумма: `Σ` месячных прибылей `=` прибыль за всё время (теорема T-4).

---

### Лист 4. `Балансы карт`

Матрица: строки — фактические даты обновлений, столбцы — карты (включая архивные),
последний столбец — общий капитал.

- Значения заполнены по LOCF: в ячейке всегда актуальный на эту дату баланс.
- Ячейки, где в этот день **не было** фактического обновления, помечаются светлым фоном —
  видно, где данные перенесены, а где введены.
- Даты вне периода жизни карты (до создания, после архивирования) остаются пустыми — не нулевыми.
- Архивные карты помечены в заголовке: `Сбер2 (архив 15.08.2026)`.
- Закреплены первая строка и первый столбец.

Инвариант, проверяемый тестом: сумма строки по картам равна значению в столбце «Капитал» (T-6).

---

### Лист 5. `Карты`

| Столбец | Примечание |
|---|---|
| Карта | Текущее название (C-9) |
| Статус | Активна / Архивирована |
| Тип начального баланса | `Просто баланс` / `Прибыль` |
| Дата создания | |
| Дата архивирования | Пусто, если активна |
| Причина архивирования | Вывод / Перевод |
| Начальный баланс | Первая запись карты |
| Текущий баланс | LOCF на сегодня; для архивной — на дату архивирования |
| **Изменение баланса ₽** | Текущий − начальный |
| **Изменение баланса %** | Относительно начального, если > 0 |
| Число обновлений | |
| Дней в работе | |

**Столбцы намеренно названы «изменение баланса», а не «прибыль» и «доходность».**
Причина в §1 требований: деньги перемещаются между своими картами, поэтому по отдельной карте
это движение, а не результат. `Σ` изменений по картам `≠` прибыль пользователя, и это не ошибка.
Оговорка вынесена в примечание к заголовку и на лист `Инфо` (FR-5.4).

---

### Лист 6. `Движения капитала`

Журнал внешних потоков из `v_capital_flows`.

| Столбец | Примечание |
|---|---|
| Дата | `flow_date` |
| Карта | |
| Тип | Депозит / Вывод |
| Сумма | Знаковая: депозит `+`, вывод `−` |
| Основание | `Создание карты` / `Архивирование: вывод` |
| Накопленный поток | Кумулятивная сумма |

Этот лист делает расчёт проверяемым вручную:
`Капитал = Σ потоков + Σ прибыли`. Пользователь может пересчитать любую цифру.

---

### Лист 7. `Календарь` (скрытый)

Ежедневный ряд без пропусков (`generate_series` от первой даты до сегодня, значения по LOCF):
дата → капитал → накопленный P&L.

Нужен только для графиков: на неравномерных датах линейный график Excel искажает время.
Лист скрыт, чтобы не путать его с фактическими наблюдениями. `Динамика` остаётся источником
истины по фактическим датам (§9).

---

### Лист 8. `Инфо`

- Дата и время формирования, таймзона, валюта `RUB`.
- Версия финансовой модели и версия приложения.
- Формулы: `P&L = Капитал(конец) − Капитал(начало−1) − Внешние потоки`.
- Оговорки:
  1. Прибыль считается от общего капитала, а не как сумма по картам.
  2. Изменение баланса отдельной карты — не прибыль по этой карте.
  3. Внешние потоки возникают только при создании и архивировании карт; пополнение карты
     из внешнего источника будет учтено как прибыль (C-7).
  4. Пропущенные дни не заполняются: P&L считается за фактический интервал.

## 3. Оформление

| Элемент | Правило |
|---|---|
| Деньги | `# ##0.00 ₽`, отрицательные красным |
| Дельты денег | `+# ##0.00 ₽;[Red]−# ##0.00 ₽` |
| Проценты | `+0.00%;[Red]−0.00%`; неопределённое — пустая ячейка |
| Даты | `dd.mm.yyyy` |
| Заголовки | Жирный, фиксированный фон, закреплённая строка |
| Таблицы | Оформлены как Excel Table (ListObject) — даёт автофильтр и структурные ссылки |
| Условное форматирование | Цветовая шкала на `P&L ₽`, шкала данных на капитале |
| Ширина столбцов | Автоподбор по содержимому |
| Порядок дат | По возрастанию на всех листах |
| Пустое значение | Пустая ячейка, никогда `0` и никогда `«—»` в числовом столбце |

Последнее правило важно: `0` в числовом столбце означает «изменение равно нулю», а пустая
ячейка — «значение не определено». В Telegram то же самое отображается как `—`.

| XL-03 | Присутствуют части `xl/charts/chart*.xml` — графики действительно записаны |
| XL-04 | Числовые ячейки записаны числами, не текстом |

| XL-06 | `Σ` месячных прибылей = прибыль за всё время (T-4) |
| XL-07 | Отчёт пользователя A не содержит ни одного значения пользователя B |
| XL-08 | Пользователь без карт: отчёт формируется, разделы пусты, ошибок нет |

| XL-11 | 10 лет × 20 карт: файл формируется в пределах лимита памяти и 50 МБ Telegram |
