# izicrm — Telegram: экраны и state machine

Handlers не содержат бизнес-логики (FR-6.3). Все многошаговые сценарии — явная state machine (FR-6.4).

---

## 1. Главный экран

Вёрстка задана заказчиком 23.08.2026 и заменяет макет §10 исходных требований.
Числа в присланном образце были черновыми — разбор в §1.2, скорректированная версия в §1.1.

### 1.1. Целевой вид

```
В работе:     681 466 ₽
Заморожено:   318 861 ₽
Всего:      1 000 327 ₽

Сегодня        [+327 ₽ / +0.03%]
Август         [+10 562 ₽ / +1.07%]

В работе:

🟢 Сбер 7121*    124 276 ₽
                 [+200 ₽ / +0.16%]

🔵 Втб 0134*     557 190 ₽
                 [+0 ₽ / 0.00%]

Заморожено:

🔴 Альфа 7131*   318 861 ₽
                 [+127 ₽ / +0.04%]

[🔄 Обновить балансы]
[➕ Пополнить]  [❄️ Расход]
[⚙️ Настройки]
```

Числа выше согласованы между собой и удовлетворяют инвариантам модели:

- `124 276 + 557 190 = 681 466` — сумма в работе (WorkCap)
- `318 861` — заморожено (FrozenCap)
- `681 466 + 318 861 = 1 000 327` — всего (T-6)
- `200 + 0 + 127 = 327` — сумма изменений равна дневному P&L, потому что в этот день
  не было создания, пополнения, перевода остатка и потери (`financial-model.md` §5.6)
- `327 / 1 000 000 = 0.0327%` → `0.03%` при `ROUND_HALF_UP`
- `10 562 / 989 765 = 1.0671%` → `1.07%`

Строка «Заморожено» и одноимённая графа скрываются, если FrozenCap = 0.

### 1.2. Разбор чисел присланного образца

Зафиксировано для истории: в образце ни одна из четырёх групп чисел не сходилась.
Это не критика — образец задавал вёрстку. Но в реализации такие значения появиться не могут,
и каждый пункт закрыт тестом.

| Что в образце | Проблема | Тест |
|---|---|---|
| Материалы `124 276 + 318 861 + 678 146 = 1 121 283`, а показано `1 000 327` | Расхождение `120 956 ₽`: сумма материалов не равна общему балансу | UI-01, T-6 |
| `Сегодня +327 ₽ / +2.56%` | При базе `1 000 000` процент равен `0.0327%`. Для `2.56%` база должна быть `12 773 ₽` — это не капитал | UI-14 |
| `Август +10 562 ₽ / +12.2%` | При базе `989 765` процент равен `1.07%`. Для `12.2%` база должна быть `86 574 ₽` | UI-14 |
| У всех трёх материалов одинаковая дельта `+124 244 / +110%` | Дельты не могут совпадать при разных балансах. Восстановленные предыдущие значения дают `388 262%`, `64%` и `22%` — ни одно не равно `110%`. Сумма дельт `372 732 ₽` превышает дневную прибыль `327 ₽` в 1 140 раз | UI-01, PT-08 |

### 1.3. Правила отображения

| Элемент | Правило |
|---|---|
| Заголовок дневного блока | `Сегодня`, если обновление было сегодня; иначе фактическая дата последнего обновления (C-14) |
| Интервал > 1 дня | Добавляется `за N дней` (§5.2 модели) |
| Проценты | 2 знака, `ROUND_HALF_UP` (C-5) |
| Разделитель разрядов | Узкий пробел U+202F, символ `₽`. В образце были `1.000.327р` — точки как разделитель и `р` вместо `₽`; см. C-21 |
| Много материалов | Пагинация при превышении лимита 4096 символов |

Состояния значений:

| Ситуация | Отображение |
|---|---|
| Нет предыдущего дня | `—` вместо P&L и процента (FR-5.6) |
| База процента ≤ 0 | `+30 000 ₽ (—)` (C-2) |
| Нет материалов | Онбординг: `Пока нет ни одного материала` + `[➕ Пополнить]` |
| Материалы в тексте | Список в сообщении; кнопок материалов на главном нет |
| Все материалы архивированы | `0 ₽`, P&L `—` |
| Все в работе заморожены | Всего > 0, «в работе» = `0 ₽`, графа работы пуста |
| Материал создан после `prev` | `новый` вместо изменения (§5.6 модели) |
| Материал заморожен | строка в графе «Заморожено»; разморозка — Расход → Вернуть в оборот |

### 1.4. Словарь интерфейса

Термины интерфейса и кода расходятся сознательно (C-18). Перевод живёт только
в `interface/telegram/views` — ниже слоя `interface` слово «материал» не встречается.

| В интерфейсе | В коде и БД |
|---|---|
| материал | `Card`, `cards`, `cardId` |
| список материалов | `listUserCards` |
| в работе | `isWorking`, `WorkCap` |
| заморожено | `isFrozen`, `FrozenCap` |
| пополнить | `topUpUserCard` |
| расход | заморозка, `freezeUserCard` |
| удалить материал | архивирование, `archiveUserCard` |
| стикер материала | `cards.icon` |

Правило: если новый текст экрана требует слова «карта» — это ошибка перевода, а не
исключение. Обратное тоже верно: `Material` в именах типов и таблиц не появляется.

### 1.5. Нерешённые вопросы по этому экрану

Открытых вопросов по главному экрану нет. Закрыты 23.08.2026: C-17, C-18, C-19, C-20, C-21.
24.08.2026: C-26 (пополнение), C-27 (две графы), C-28 (меню), C-29 (без типа PROFIT).

### 1.6. Раздел «Настройки» (C-19)

Главный экран несёт четыре кнопки повседневного учёта, всё остальное — второй уровень.

```
Настройки

[📊 Отчёт в Excel]
[✏️ Переименовать материал]
[🎨 Сменить стикер]
[🗑 Удалить материал]
[📁 Архив материалов]
[◀️ Назад]
```

`Удалить материал` перенесено сюда с главного экрана (C-28): редкое действие с тремя
ветвями судьбы остатка не должно стоять рядом с ежедневным обновлением.

`Архив материалов` — список только для чтения: разархивирование вне scope v1 (C-9).
Он существует, чтобы пользователь видел, что удалённые материалы не исчезли.

## 2. Состояния FSM

Размеченное объединение. Payload валидируется Zod при чтении из `dialog_states`.
**Денежные суммы в payload — строки** (ADR-005).

```ts
type DialogState =
  | { t: 'Idle' }
  | { t: 'CardCreateName' }
  | { t: 'CardCreateBalance';   name: string }
  | { t: 'CardCreateIcon';      name: string; amount: string }
  | { t: 'CardRenameName';      cardId: CardId }
  | { t: 'CardSetIcon';         cardId: CardId }
  | { t: 'TopUpSelect' }
  | { t: 'TopUpAmount';         cardId: CardId; businessDate: BusinessDate }
  | { t: 'FreezeSelect' }
  | { t: 'SpendSelect' }
  | { t: 'UnfreezeSelect' }
  | { t: 'SpendAmount';         cardId: CardId; businessDate: BusinessDate }
  | { t: 'FrozenCardMenu';      cardId: CardId }
  | { t: 'BalanceUpdateAmount'; queue: CardId[]; index: number;
                                businessDate: BusinessDate; done: UpdatedCard[] }
  | { t: 'ArchiveConfirm';      cardId: CardId }
  | { t: 'ArchiveDisposition';  cardId: CardId; lastBalance: string }
  | { t: 'ArchiveTarget';       cardId: CardId; amount: string }
  | { t: 'ReportBuilding' };
```

Один тип состояния `BalanceUpdateAmount` обслуживает и одну карту, и все: разница только
в длине `queue` (FR-4.3). Второй сценарий не пишется. В очередь «все» попадают только
незамороженные карты (C-27).

`CardCreateIcon` — выбор декоративного стикера (C-20), необязательный шаг. Он последний,
поэтому карта создаётся одной записью после него. Типа начального баланса нет (C-29):
`capital_in = amount` всегда. Стикер меняется позже наравне с названием.

`businessDate` фиксируется при входе в состояние и не пересчитывается на последующих шагах —
иначе диалог, начатый 31 августа в 23:59, разложил бы записи по двум месяцам (C-11).

## 3. Таблица переходов

Функция перехода чистая: `reduce(state, event, ctx) → { next, effects }`. Тестируется без Telegram.

> Сами переходы вёрсткой от 24.08.2026 затронуты в точках входа: `cb:topup`, `cb:expense`,
> `cb:card_add` живёт под «Пополнить», `cb:card_archive` — под настройками (C-28).
> Состояние `ArchiveConfirm` по-прежнему архивирует (C-17). `CardCreateKind` снят (C-29).

| Состояние | Событие | Переход | Эффект |
|---|---|---|---|
| `Idle` | `/start`, `cb:home` | `Idle` | Показать главный экран |
| `Idle` | `cb:topup` | `Idle` | Меню пополнения: добавить / пополнить существующий |
| `Idle` | `cb:card_add` | `CardCreateName` | Запросить название |
| `CardCreateName` | текст | `CardCreateBalance` | Проверить название: непустое, ≤ 64, нет активного дубля |
| `CardCreateName` | текст, дубль | `CardCreateName` | «Материал с таким названием уже есть» |
| `CardCreateBalance` | текст | `CardCreateIcon` | Разобрать сумму; предложить стикер |
| `CardCreateBalance` | текст, невалиден | `CardCreateBalance` | Показать правила ввода |
| `CardCreateIcon` | `cb:icon:<n>` | `Idle` | Создать карту со стикером; `capital_in = amount` |
| `CardCreateIcon` | `cb:skip` | `Idle` | Создать карту с `icon = NULL` |
| `CardCreateIcon` | `cb:icon:<n>`, `n` вне белого списка | `CardCreateIcon` | Игнорировать: `callback_data` недоверенный |
| `Idle` | `cb:topup_pick` | `TopUpSelect` | Список материалов в обороте |
| `TopUpSelect` | `cb:topup` | `Idle` | Вернуться в меню пополнения |
| `TopUpSelect` | `cb:topup_card:<id>` | `TopUpAmount` | Guard: в работе; запросить новый баланс |
| `TopUpAmount` | текст, `Y >` текущего | `Idle` | Пополнить: `amount = Y`, `capital_in += Y − текущий` |
| `TopUpAmount` | текст, невалиден или `Y ≤` текущего | `TopUpAmount` | Правила ввода; состояние не меняется |
| `Idle` | `cb:expense` | `Idle` | Меню расхода: заблокировать / потратил / вернуть в оборот |
| `Idle` | `cb:freeze_pick` | `FreezeSelect` | Список материалов в работе |
| `FreezeSelect` | `cb:expense` | `Idle` | Вернуться в меню расхода |
| `FreezeSelect` | `cb:freeze:<id>` | `Idle` | Заморозить; P&L = 0 |
| `Idle` | `cb:unfreeze_pick` | `UnfreezeSelect` | Список замороженных |
| `UnfreezeSelect` | `cb:expense` | `Idle` | Вернуться в меню расхода |
| `UnfreezeSelect` | `cb:frozen:<id>` | `FrozenCardMenu` | Карточка замороженного |
| `Idle` | `cb:spend_pick` | `SpendSelect` | Список в работе и замороженных |
| `SpendSelect` | `cb:expense` | `Idle` | Вернуться в меню расхода |
| `SpendSelect` | `cb:spend_card:<id>` | `SpendAmount` | Запросить новый баланс |
| `SpendAmount` | текст, `Y <` текущего | `Idle` | Трата: `amount = Y`, `capital_out += текущий − Y` |
| `SpendAmount` | текст, невалиден или `Y ≥` текущего | `SpendAmount` | Правила ввода; состояние не меняется |
| `Idle` | `cb:frozen:<id>` | `FrozenCardMenu` | Карточка замороженного |
| `FrozenCardMenu` | `cb:unfreeze:<id>` | `Idle` | Разморозить; P&L = 0 |
| `FrozenCardMenu` | `cb:upd_one:<id>` | `BalanceUpdateAmount` | `queue` = `[id]` после проверки владения |
| `Idle` | `cb:upd_all` | `BalanceUpdateAmount` | `queue` = карты в работе по алфавиту; `businessDate` = сегодня |
| `Idle` | `cb:upd_one:<id>` | `BalanceUpdateAmount` | `queue` = `[id]` после проверки владения |
| `BalanceUpdateAmount` | текст | тот же / `Idle` | Записать баланс; `index++`; при исчерпании — итог и `Idle` |
| `BalanceUpdateAmount` | текст, невалиден | тот же | Показать правила; `index` не меняется |
| `BalanceUpdateAmount` | `cb:skip` | тот же / `Idle` | Пропустить карту без записи (LOCF сохраняет прежний баланс) |
| `Idle` | `cb:card_rename:<id>` | `CardRenameName` | Запросить новое название |
| `CardRenameName` | текст | `Idle` | Переименовать; уникальность проверяется заново |
| `Idle` | `cb:card_archive:<id>` | `ArchiveConfirm` | Спросить подтверждение |
| `ArchiveConfirm` | `cb:yes`, остаток = 0 | `Idle` | Архивировать, `reason = WITHDRAWN`, поток 0 |
| `ArchiveConfirm` | `cb:yes`, остаток ≠ 0 | `ArchiveDisposition` | Спросить судьбу остатка (C-17) |
| `ArchiveDisposition` | `cb:withdrawn` | `Idle` | Архивировать `WITHDRAWN`; поток `−X`; P&L не меняется |
| `ArchiveDisposition` | `cb:lost` | `Idle` | Архивировать `LOST`; потока нет; P&L уменьшается на `X` |
| `ArchiveDisposition` | `cb:transferred` | `ArchiveTarget` | Показать список карт-получателей |
| `ArchiveTarget` | `cb:target:<id>` | `Idle` | Транзакция: обнулить источник, прибавить остаток получателю, архивировать `TRANSFERRED`, потока нет |
| `Idle` | `cb:settings` | `Idle` | Показать раздел настроек (C-19, C-28) |
| `Idle` | `cb:report` | `ReportBuilding` | Rate limit; сформировать и отправить файл |
| `ReportBuilding` | завершение | `Idle` | Отправить документ |
| любое | `cb:cancel` | `Idle` | Сбросить состояние, показать главный экран |
| любое | истёк `expires_at` | `Idle` | «Диалог отменён из-за неактивности», показать главный экран |

Guard-и, выполняемые перед **каждым** переходом, затрагивающим карту:

1. Карта существует и принадлежит `userId` (`getUserCard(userId, cardId)`).
2. Карта активна, если операция требует активной.
3. `state_rev` из `callback_data` совпадает с текущим — иначе `StaleCallbackError`.

Guard-и — единственное место, где проверяется владение. Они не полагаются на то, что кнопка
была отрисована для этого пользователя (FR-1.5).

## 4. Экраны диалогов

### Создание материала

```
Введите название материала:                    [Отмена]
→ Сбер1

Сбер1
Введите текущий баланс:                        [Отмена]
→ 10000

Эта сумма — точка отсчёта, прибылью не считается.
Прибыль появится, когда обновите баланс.
```

Вопроса «это прибыль?» нет (C-29). Дальше — необязательный стикер, затем создание
с `capital_in = amount`.

### Пополнение существующего материала

```
Пополнить

[➕ Добавить материал]
[💵 Пополнить материал]
[◀️ Назад]
```

После выбора материала:

```
Сбер1
Сейчас: 80 000 ₽

Введите новый баланс:
[Отмена]
→ 90000

Пополнено на 10 000 ₽. Прибыль не изменилась.
Сбер1 · 90 000 ₽
```

Вводится абсолютный баланс, как на карте. Если ввести 80 000 или меньше — ошибка:
уменьшение баланса это расход, не пополнение.

### Расход

```
Расход

[❄️ Заблокировать материал]
[💸 Потратил / вывел]
[♻️ Вернуть в оборот]
[◀️ Назад]
```

Заморозка:

```
Какой материал заблокировать?

[🟢 Сбер 7121*  · 124 276 ₽]
[🔵 Втб 0134*   · 557 190 ₽]
[◀️ Назад]
```

После выбора материал исчезает из «В работе» и появляется в «Заморожено».
Подтверждение: «Альфа заморожена. Во „Всего“ она осталась, прибыль не изменилась».

Трата:

```
Сбер1
Сейчас: 80 000 ₽

Введите новый баланс после траты:
[Отмена]
→ 70000

Выведено 10 000 ₽. Прибыль не изменилась.
Сбер1 · 70 000 ₽
```

Если ввести 80 000 или больше — ошибка. Карта не удаляется, даже при нуле.

Карточка замороженного (Расход → Вернуть в оборот → материал):

```
🔴 Альфа 7131* · 318 861 ₽
Заморожено

[♻️ Вернуть в оборот]
[🔄 Обновить баланс]
[◀️ Назад]
```

### Обновление балансов

```
Сбер1  (1 из 3)
Предыдущий баланс: 1 000 ₽

Введите текущий баланс:
[⏭ Пропустить]  [Отмена]
```

После прохода:

```
Обновлено 3 карты · 20 августа

116 000 ₽
+1 200 ₽ (+1.05%)

Сбер1     10 500 ₽   +500 ₽
Сбер2     21 300 ₽   +700 ₽
Тинькофф   7 800 ₽     +0 ₽
```

При пропуске части карт итог включает строку `Пропущено: 1` — не предупреждение, а факт.

### Выбор стикера при создании (C-20)

```
Сбер1 · 10 000 ₽ · просто баланс

Выберите стикер:
[🟢] [🔴] [🔵] [🟡] [🟣] [⚪]
[⏭ Без стикера]  [Отмена]
```

Стикер декоративен: на расчёты не влияет и меняется позже в настройках. Выбор из белого
списка, произвольный текст не принимается — иначе он попал бы в строку материала и сломал
вёрстку. `callback_data` вне списка игнорируется как недоверенный ввод.

### Удаление материала с ненулевым остатком (C-17)

```
Удалить «Сбер2»?
Текущий баланс: 20 000 ₽

История сохранится и останется в отчётах.
Что стало с этими деньгами?

[↔️ Перевёл на другую карту — прибыль не изменится]
[💸 Вывел: снял или потратил — прибыль не изменится]
[📉 Потерял — это убыток 20 000 ₽]
[Отмена]
```

Каждая кнопка называет последствие для прибыли прямо в тексте. Это не многословность:
три варианта дают `0`, `0` и `−20 000 ₽` на одних и тех же данных, и отличить их система
сама не может (`docs/financial-model.md` П-4, П-5, П-5б). Формулировки «плюс» и «минус»
из первоначальной вёрстки отклонены — они допускали три несовместимых прочтения (C-17.1).

«Перевёл» ведёт к выбору карты-получателя и в одной транзакции переносит остаток.
«Вывел» пишет поток `−20 000`. «Потерял» не пишет потока, и падение капитала становится
убытком (T-9).

Третий вариант — единственная операция в системе, уменьшающая прибыль по решению
пользователя, поэтому в подтверждении сумма убытка называется цифрой. Показать её
после нажатия было бы поздно.

При остатке `0` вопрос не задаётся: любой ответ дал бы одинаковый результат, а лишний
экран только провоцирует ошибку.

## 5. Протокол `callback_data`

Формат: `v1:<action>:<id>:<rev>`, лимит Telegram — 64 байта.

| Часть | Назначение |
|---|---|
| `v1` | Версия протокола; неизвестная версия → перерисовка экрана |
| `action` | Короткий код действия |
| `id` | ID сущности, **недоверенный**: всегда перепроверяется по `user_id` |
| `rev` | `state_rev` пользователя на момент отрисовки кнопки |

`rev` решает конкретную проблему: пользователь может нажать кнопку в старом сообщении,
пролистав историю чата. Без проверки ревизии это привело бы к повторной записи баланса или
к операции над уже архивированной картой. Несовпадение `rev` → «Кнопка устарела» + перерисовка.

Идемпотентность на уровне доставки — `processed_updates(update_id)` (ADR-009): повторная
доставка апдейта Telegram не создаёт вторую запись.

## 6. Ошибки и граничные ситуации

| Ситуация | Поведение |
|---|---|
| Невалидная сумма | Правила ввода, состояние не меняется (FR-6.5) |
| Более 2 знаков после запятой | «Копейки — не более двух знаков». Без молчаливого округления (C-12) |
| Сумма вне `±10^15` | «Слишком большое значение» |
| Дубль названия | «Материал с таким названием уже есть» |
| Чужой `card_id` в callback | Нейтральное «Материал не найден» + запись в лог безопасности |
| Карта архивирована в процессе прохода | Guard пропускает её, проход продолжается |
| Карта заморожена в процессе прохода «все» | Guard пропускает её, проход продолжается |
| Нет материалов в работе при `cb:upd_all` / заморозке | «Нет материалов в работе» + `[➕ Пополнить]` |
| Пополнение `Y ≤` текущего | «Новый баланс должен быть больше текущего» |
| Трата `Y ≥` текущего | «Новый баланс должен быть меньше текущего» |
| Диалог неактивен > 30 минут | Сброс в `Idle` при следующем действии |
| Повторный `cb:report` | Rate limit: не чаще 1 раза в минуту |
| Пользователь заблокировал бота (403) | Отметить `blocked_at`, прекратить отправку |
| Сообщение > 4096 символов | Пагинация списка карт |
