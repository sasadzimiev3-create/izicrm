# izicrm — инструкции для агентов

Telegram-бот для персонального учёта балансов банковских карт и расчёта P&L. Валюта — только RUB.

**Текущий статус: архитектурный этап завершён, реализация не начата.**
Не начинать реализацию бота без явной команды.

## Пять правил, нарушение которых недопустимо

### 1. Один источник истины для P&L

Вся прибыль считается через `domain/finance/pnl.ts:periodPnl`. Дневной, месячный и общий
P&L — её параметризации. Новая формула прибыли где-либо ещё — ошибка, а не оптимизация.

```
PnL(u, A, B) = Cap(u, B) − Cap(u, A − 1 день) − NetFlow(u, [A, B])
```

### 2. Основной P&L — от общего капитала, а не от суммы карт

Деньги перемещаются между своими картами пользователя. Сумма изменений по картам ≠ прибыль.
Метрика по карте называется `balanceChange`, никогда `profit`.

### 3. Деньги — только `Decimal`

Никогда `number`, `parseFloat`, `Math.round`, `toFixed` для расчётов, JSON-числа для сумм,
`SUM()` по деньгам в SQL. Единственное разрешённое `Decimal → number` — запись ячейки Excel.

### 4. Каждый запрос скоупится по `user_id`

`getUserCard(userId, cardId)`, не `getCard(cardId)`. Плюс RLS как второй барьер.
`card_id` из `callback_data` всегда недоверенный.

### 5. Финансовые данные не удаляются и не изменяются

Append-only. Исправление — новая запись, вытесняющая предыдущую логически.
`DELETE` и `UPDATE` сумм заблокированы триггером и правилом в БД.

## Границы слоёв

```
interface/telegram → application → domain ← infrastructure → PostgreSQL
```

| Слой | Содержит | Не содержит |
|---|---|---|
| `domain` | чистые функции, `Decimal`, формулы | I/O, SQL, grammY, `Date.now()` |
| `application` | сценарии, транзакции, порты | SQL, знание о Telegram |
| `infrastructure` | репозитории, адаптеры | бизнес-логику |
| `interface` | handlers, FSM, рендер текста | арифметику, SQL |

Текущая дата в `domain` **передаётся параметром** — расчёты детерминированы и тестируемы.

## Работа с деньгами

```ts
// ПЛОХО
const total = cards.reduce((s, c) => s + Number(c.balance), 0);
const pct = (delta / prev) * 100;

// ХОРОШО
const total = cards.reduce((s, c) => s.plus(c.balance), Money.zero());
const pct = percentChange(delta, prev); // → PercentResult, учитывает base <= 0
```

Процент никогда не возвращается голым числом: только `PercentResult`, чтобы
неопределённое значение нельзя было случайно отобразить как `0%`.

## Требования к новому финансовому коду

Каждый финансовый метод обязан иметь:

1. Понятное имя, отражающее формулу
2. Docstring с формулой и ссылкой на раздел `docs/financial-model.md`
3. Unit-тесты, включая границы: нулевая база, отсутствие предыдущего дня, очень большие
   значения, дробные значения, отрицательный баланс
4. Обновление матрицы тестов в `docs/financial-model.md` §10 при добавлении сценария

Покрытие `src/domain/finance/**` — 100% строк и ветвей, это CI-гейт.

## Прежде чем менять финансовую логику

1. Найти соответствующее требование или пункт `C-*` в `docs/requirements.md`.
2. Если требование неоднозначно — **не догадываться**: зафиксировать противоречие в реестре
   и спросить. Бизнес-логику, которой нет в требованиях, не придумывать.
3. Обновить `docs/financial-model.md`, затем тесты, затем код — в этом порядке.
4. Проверить, что теоремы T-1…T-8 по-прежнему выполняются.
